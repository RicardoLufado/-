# ADR-010：盘中运行以实时价为起点；晋级线的人群项从校准日起算

- Status: Accepted
- Date: 2026-10-12

## Context

10-12（周一）13:57 用户发来 App 录屏：仍持有 IM2612 多 3 手，IM 从 10-09 结算价 7021.4 跌到约 6918，
期货权益从 1,063,984.58 降到 1,002,184.58。用户要求「导入最新数据重新计算」。原引擎有两个问题：

1. 起点永远是日线最后一天 t0（盘中仍是 10-09）。把盘中权益填进去后，情景还会把 10-12 再模拟一遍，
   而且 2612 价格、基差、剩余天数都停在 10-09。
2. 相对口径的晋级线 = c0 + Nc × 沪深300 从 **t0** 起的涨跌。c0 是用 10-09 周榜推算的，
   t0 往后推进（或盘中）时，人群多单在校准日之后已经实现的盈亏被丢掉了：
   你今天的亏损算进了权益，别人今天的亏损却没算进晋级线，模型会以为你落后更多，从而推荐更激进的仓位。

## Options Considered

1. 维持原样，只在收盘后（晚上）运行：问题 2 仍在，且盘中无法给建议。
2. 账户填盘中权益，其余不变：问题 1、2 都在，结果偏激进。
3. 盘中以实时价为起点，并给晋级线加「校准日」：
   - 起点改为现在：F0 = 新浪实时价，指数按同一涨跌幅平移（基差率不变），今天视为已过去；
   - 权益：`account.json` 可写 `mark_prices`（抄权益时 App 的现价），从该价盯市到当前价；
   - 晋级线：人群项 = Nc × 沪深300 从 `threshold.anchor_date` 收盘到期末的涨跌
     = 已实现部分（校准日 → 起点，盘中部分用 IF2612 涨跌近似）+ 模拟部分。

## Decision

选方案 3。触发条件：今天是交易日、已过 09:30、日线还停在 t0 之前、有 IF2612 实时价。
`config/strategy.yaml` 新增 `threshold.anchor_date`（当前 2026-10-09），每次用新周榜校准时一并更新。
`latest.json` 新增 `start`，`threshold` 新增 `base_low/base_high/shift/anchor_date/index_move_since_anchor`，
`low/high` 改为平移后的区间。

## Why

- 起点和权益、价格、剩余天数在同一时刻，没有重复模拟今天。
- 晋级线和你的盈亏用同一段行情：大盘下跌时你亏、持多单的其他人也亏，排名只看相对差距。
- 不改目标函数和晋级线的基础区间（仍是周榜推算的 0–6 万），只修正时间口径。

## Consequences

- 盘中可以随时重算并得到一致的建议；收盘后到新浪日线更新前（约 15:15–20:00）同样以收盘时的实时价为起点。
- 盘中部分用 IF2612 的涨跌近似沪深300（忽略当天基差变化，误差通常在 0.1% 以内）。
- 盘中抄权益时必须同时抄现价，否则当天不盯市（直接用填写的权益）。
- 每次用新周榜重新估计 `excess_low/high` 时，要把 `anchor_date` 改成那期周榜的日期。
