# ADR-007：定时按上海时间写，开盘前和晚上各设 3 个时间点

- Status: Accepted
- Date: 2026-10-09

## Context

最初的定时是北京 08:45 和 15:35（写成 UTC cron），实际观察到：
- 新仓库的定时任务第一天一次都没触发；后来触发了，也延迟了 5–6 小时（10-09 晚上那三次在凌晨 02:17–03:29 才跑）。
- 16:18 时，新浪的指数日线还没有当天收盘，收盘后马上跑算的仍是前一天的数据。
- 用户希望按上海时间设定。

## Options Considered

1. 保持两个 UTC 时间点。
2. 用 `timezone: Asia/Shanghai` 写 cron，开盘前和晚上各 3 个冗余时间点。
3. 用外部触发器：Claude 定时任务，或 cron-job.org 带令牌调用 workflow_dispatch。

## Decision

选方案 2：
- 开盘前 08:25 / 08:45 / 09:05，晚上 20:05 / 21:05 / 22:05，周一至周五，上海时间；
- 外部触发器暂不启用，作为备选；
- 页面突出显示「计算时间」，超过 1 天标红。

## Why

- 上海没有夏令时，写成上海时间和换算成 UTC 是同一个时刻，但更直观，用户能看懂。
- 多个时间点相互兜底，跑到哪次都行，最新一次覆盖之前的结果。
- 晚上跑能拿到当天完整的收盘数据；即使延迟到凌晨，也能在第二天开盘前完成。
- 外部触发器需要令牌，或者会消耗额度，暂时没有必要。

## Consequences

- `timezone` 写法依据的是二手资料（GitHub 2026-03 更新）。工作流文件已经被 GitHub 接受，但是否真按上海时间触发，还要继续观察。
- 用户开盘前要看一眼「计算时间」，必要时手动 Run workflow。
- 每天最多跑 6 次，加上推送触发的运行；公开仓库的 Actions 免费。
