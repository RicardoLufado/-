# ADR-011：开仓保证金上限从 70% 放宽到 80%

- Status: Accepted
- Date: 2026-10-18
- Supersedes ADR-004（「开仓保证金 ≤ 70% 期货权益」这一条；目标函数和搜索方法不变）

## Context

10-09 以来大盘连续下跌（沪深300 约 −3.4%，中证1000 更多），用户持 IM 多 2 手，期货盈利约 −16 万，
落后估计的晋级线下沿约 12.4 万（10-16 收盘数据）。10-14 用户明确：只要晋级概率最大，不把爆仓风险本身当作约束。
10-16 收盘数据下，3 手 IM 的晋级概率约 36%，但保证金占权益 70.6%，被 70% 上限排除；
上限内的最优是 IF 多 1 + IM 多 2，约 34%。70% 是开赛时为防爆仓定的规则，不是交易所规定（交易所在权益低于保证金时强平）。

## Options Considered

1. 保持 70%：最优 IF 1 + IM 2，晋级约 34%。
2. 放宽到 80%：3 手 IM 等组合变为可选，晋级概率约高 2 个百分点；离强平更近。
3. 取消上限（100%）：允许把保证金加到接近强平线，开仓当天小幅波动就可能被强平；模型只在收盘检查爆仓，
   会低估这种情况。

## Decision

选方案 2：`config/strategy.yaml` 的 `risk.margin_cap` 改为 0.80。爆仓判断（`liq_ratio: 1.0`）不变，
模型仍把爆仓路径算作未晋级，所以晋级概率已包含爆仓的代价。

## Why

- 用户的目标只有晋级概率，落后时理论上应加大风险（Browne 1999），70% 上限在当前状态下压低了晋级概率。
- 80% 足以容纳 3 手 IM，同时留出约 20% 的缓冲，避免开仓后小幅波动就被强平；100% 时模型的「收盘才检查爆仓」
  假设会明显偏乐观。

## Consequences

- 推荐仓位可能更重，爆仓概率可能高达 20%–30%（网页上照常显示）。
- 状态回到「锁定」或领先时，模型会自动建议减仓，上限只影响落后时能加到多重。
- 如果用户以后想收紧或放开，改 `risk.margin_cap` 并新增 ADR。
